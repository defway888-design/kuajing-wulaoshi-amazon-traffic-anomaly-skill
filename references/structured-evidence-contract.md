# 流量诊断结构化证据契约

## 1. 业务边界

本契约用于把流量诊断结果交给跨境吴老师周数据分析主 Skill。流量诊断 Skill 只提供异动事实、诊断证据和诊断结论，不生成行动建议，不区分可控制因素与不可控制因素，不输出 P0/P1。

运营可读报告与结构化证据必须由同一次诊断、同一个内部证据对象生成。禁止解析 Word 或自然语言报告后再次推理生成结构化证据。

## 2. 诊断总状态

- `完整完成`：核心条件和全部计划验证项均完成。
- `可用但有证据缺口`：核心条件完成，已形成可复核结论，但一个或多个辅助验证项缺失。
- `诊断失败`：核心条件缺失、冲突或无法形成可复核结论。

核心条件包括：父 ASIN、站点、流量异动方向、当前比较窗口、基准比较窗口、两期核心流量值、等天数或已完成日均归一化、核心数据来源无冲突，以及至少能够形成“存在支持因素”或“已完成核心排查但无因素命中”的可复核结论。

辅助缺口包括：Seller ID、站外推广、联盟客推广、配送辅助证据、部分 Listing 辅助字段及其他不影响核心流量事实成立的证据。辅助缺口不得单独把整份诊断降为 `诊断失败`。

## 3. 固定字段

每个命中因素输出一行，字段顺序固定为：

1. `记录键`
2. `父ASIN`
3. `异动指标`
4. `异动方向`
5. `因素编码`
6. `因素名称`
7. `当前期证据`
8. `对比期证据`
9. `数据来源`
10. `证据状态`
11. `证据缺口`
12. `诊断结论`

字段规则：

- `记录键`：上游提供时原样返回；独立运行未提供时写 `未提供`，不得自行冒充正式记录键。
- `异动指标`：固定为 `流量异动`。
- `异动方向`：只允许 `流量增加` 或 `流量减少`。
- `当前期证据`、`对比期证据`：必须各自包含实际日期窗口和可核验数值或状态。
- `数据来源`：使用业务数据源名称，可列多个，不写底层工具前缀或原始字段路径。
- `证据状态`：命中因素只允许 `支持证据` 或 `候选支持证据`。
- `证据缺口`：无缺口写 `无`；有缺口时写具体缺失项及其对结论的影响。
- `诊断结论`：只说明该因素与流量方向的证据关系，不写行动建议。

没有因素命中但核心诊断完成时，结构化证据行可以为空，诊断总状态仍可为 `完整完成` 或 `可用但有证据缺口`，并在总诊断结论中写明 `已完成核心排查，暂无因素命中`。

## 4. 因素编码

| 因素编码 | 因素名称 |
|---|---|
| `traffic_inventory` | 到货或断货变化 |
| `traffic_ad_spend` | 广告花费变化 |
| `traffic_deals` | Deals开始或结束 |
| `traffic_offsite` | 站外推广开始或停止 |
| `traffic_variation` | 变体增加或拆分 |
| `traffic_listing_status` | Listing状态异常或恢复 |
| `traffic_organic_rank` | 自然搜索关键词排名变化 |
| `traffic_organic_keyword_count` | 自然搜索关键词数量变化 |
| `traffic_keyword_trend` | 主要关键词搜索趋势变化 |
| `traffic_affiliate` | 联盟客推广开始或停止 |

不得临时改写已定义编码。同一因素存在多条明细时，保留一行因素记录，并在当前期证据和对比期证据中汇总关键明细。

## 5. 返回对象

上游调用时至少返回：

```text
诊断总状态
核心阻断原因
证据缺口清单
结构化证据行
运营可读诊断报告
```

`诊断失败` 时不得生成正式因素结论，结构化证据行返回空数组；已经取得的事实可放入阻断说明，但不能包装成正式诊断结果。
